# PolyCraft — Overnight runbook

For the unattended development session. Read this first, then [DESIGN.md](DESIGN.md) (what to build, with every
decision already made) and [TEST_PLAN.md](TEST_PLAN.md) (how it is verified). Repo-wide rules are in the root
`AGENTS.md` and `docs/agents/`; read the commands, gotchas, conventions and releases docs before the first build.

## Ground rules

- Work on branch `feat/polycraft-scaffold` (already exists). **Never push, never merge, never touch another mod**
  or the repo-wide build files, except where a step below says so.
- **Commit after each milestone** (conventional commits, e.g. `feat(polycraft): ...`) once its checks pass. Small,
  working commits beat one big one.
- **A milestone is done only when**: `./gradlew :polycraft:fabric:test` passes, `:polycraft:fabric:compileJava` and
  `:polycraft:neoforge:compileJava` both succeed, and the milestone's GameTests (if any) pass. Don't start the
  next milestone on a red build.
- **Never guess at Minecraft 26.2 APIs.** Anything marked "verify" in DESIGN.md, and any class or method you
  haven't seen in this session, is checked against decompiled source first (`mc-source-decompile` skill, check
  `.sources/` before decompiling). Names are official Mojang mappings; the identifier class is
  `net.minecraft.resources.Identifier`.
- **When blocked or unsure of a design call, don't stall and don't improvise silently.** Append an entry to
  `polycraft/OVERNIGHT-LOG.md` (what you tried, what's unclear, what you did instead), pick the most
  conservative option that keeps vanilla behaviour intact, and move on. The maintainer reviews the log in the
  morning.
- **Never change a decision in DESIGN.md.** If one turns out to be unworkable, log it, implement the closest
  safe fallback, and leave the doc alone.
- Keep vanilla behaviour as the fallback everywhere: any exception or missing data in PolyCraft's code path must
  degrade to the vanilla recipe lookup, never crash the game or block crafting.
- LF line endings; write files with the Write/Edit tools (see `docs/agents/conventions/code-style.md`).
- Use chimeric-lib's `YaclConfig` for config (see `docs/agents/conventions/scaffolding.md`), not a hand-rolled
  config class.
- Log each milestone's result (tests run, anything skipped) in `OVERNIGHT-LOG.md`, so the morning review is
  quick. Report failures faithfully; don't mark something done that isn't.

## Milestones

Do these in order. Each ends with a commit.

### M0 — Verify the ground (no feature code)

Check against decompiled 26.2 source and record the answers in `OVERNIGHT-LOG.md`:
- How crafting-table results, furnace-family cooking, the Crafter, smithing and campfire look up recipes
  (the exact methods and the input types), and where a mixin can substitute the chosen recipe.
- What the client knows about recipes (what is synced, what isn't) and how recipe-book clicks reach the server.
- How a menu/screen can add a widget, and how furnace cook progress and total time are stored.
- Whether the vanilla recipe-book page-arrow sprite ids in DESIGN.md exist.
- The 26.2 direct texture-blit call for the two 30x30 list-item textures.
- How player data and block-entity data are attached on both loaders (Architectury or loader API).

Done when: the log has an answer for each, and any DESIGN.md assumption that is wrong is flagged.

### M1 — Pure-Java core, fully unit tested

`core/`: `SignatureBuilder`, `GroupKey`, `ConflictDetector`, `ChoiceResolver`, `Rules` parsing. No Minecraft types
in the signature maths where possible. Implements every Detection edge case in DESIGN.md, the same-item-
different-count rule, the resolution order (pin > acting player > pack default > vanilla), and the 250 ms/10k
recipe budget (`PerfTest`).

Done when: every class listed under "Automated: unit" in TEST_PLAN.md exists and passes.

### M2 — Config, rules, commands, player data

`PolyCraftConfig` (all keys in the DESIGN.md table, via `YaclConfig`), `rules.json` loading from config and
datapacks with `/polycraft reload`, per-player choice storage (with pruning of stale entries and a cap), and the
commands (`conflicts`, `export`, `reset`, `reload`; `conflicts` is open to everyone, the others per the design).
Include `en_us.json` language keys for everything player-visible.

Done when: the related unit tests pass and the commands run in a GameTest or dev world.

### M3 — Crafting table end to end

`RecipeIndex` built on recipe reload, the lookup mixin, server-authoritative select/options payloads
(validated server-side, forged payloads ignored), shift-click bulk crafting, and the client button + popup
(16x16 button, 30x30 list items, vanilla scroll arrows if verified, count badge text, keyboard navigation, Esc
cancels). Placeholder textures per the "UI art" section, generated by a script in `polycraft/design/`.

Done when: the crafting GameTests in TEST_PLAN.md pass; a `mc-visual-smoke-test` screenshot of the popup with
more than `visibleOptions` entries is saved and looks sane (log the path).

### M4 — Furnace family and the pin

Furnace, smoker and blast furnace: selection, the 12x12 lock toggle, per-block pins saved with the block entity,
acting-player resolution, mid-cook switching (keep elapsed ticks, new total, nothing wasted), the re-resolve
rules (closing the GUI does not flip the recipe), and greyed-out options that can't merge into the output slot.

Done when: all furnace and pin GameTests in TEST_PLAN.md pass.

### M5 — Crafter, campfire, smithing table

Crafter (button + lock toggle, pin on the block entity, unpinned falls to pack default then vanilla), campfire
(pack default only, no UI), smithing table. Confirm the stonecutter is untouched.

Done when: the matching GameTests pass, including `stonecutter_untouched`.

### M6 — Compatibility declarations

Mark Polymorph explicitly incompatible in both loaders' metadata (`breaks`/`incompatible` in
`fabric.mod.json` and `neoforge.mods.toml`), using the mod id `polycraft`'s conflict targets: the original
`polymorph` id plus any 26.2 fork ids you can find (search the web; log each id and its source). Verify the
metadata still loads in a dev run with and without a stub of the other mod if feasible, and log how you
checked. If the loaders can't express it for some case, log it.

Done when: both loaders' metadata declare the incompatibility and the mod still launches.

### M7 — Recipe book (optional; drop it if it fights you)

Selecting a recipe in the recipe book sets the player's choice. If mapping recipe-book display ids to recipes
turns out awkward or risky, **skip this milestone**, log why, and leave it out of the README. It is not a v1
requirement.

### M8 — Polish and docs

README features and rules.json example, `CHANGELOG.md` entries under Unreleased (including the `TODO(art)`
list for the placeholder textures and unconfirmed sizes), `TEST_PLAN.md` updated to match what actually
exists, ideas Inbox untouched. Do **not** cut a release or change `mod_version`.

Done when: the full test suite is green, both loaders compile, and `OVERNIGHT-LOG.md` has a summary of what is
done, what was skipped, and every question for the maintainer.

## Out of scope tonight

Pack-level disable/lock, JEI/REI/EMI integration, the public modder API, stonecutter changes, brewing, a
release. Don't start on these even if time remains; finish verification and docs instead.

## Morning review (for the maintainer)

Read `OVERNIGHT-LOG.md` top to bottom, then check by hand what can't be automated: how the popup feels, GUI
scales 1 to 4, tooltips, and two players at one station (TEST_PLAN.md manual list).
